1. WHAT IS THIS PROJECT?
================================================================================

Anandotsav 2026 is the Sri Krishna Janmashtami celebration held at
Sri Gokul Gaushala, Birbalpura, Amritsar on Sunday, 6 September 2026.

This repository is the FULL registration platform (website + API + database).
It does four things:

  A) REGISTRATION
     People register themselves and family members. Each person gets a unique
     Entry QR code and an entry pass they can download.

  B) SEVA & CELEBRATIONS
     During registration, bhaktas can optionally opt in for:
     · Youth volunteer seva
     · Divya Panchamrit Abhishek
     · Fancy dress for kids (under 12)
     · Laddu Gopal shringar (bring murti to Utsav Mandapam before 6:00 PM)
     Staff can list and CSV-export each of these from the admin panel.

  C) REFERRAL COMPETITION
     Registered people can get a personal Krishna referral code. Friends who
     register with that code increase their count. A public leaderboard shows
     name + count only (codes are not public).

  D) EVENT CHECK-IN (SCANNER)
     On event day, staff scan each Entry QR (or type the entry code) to mark
     the bhakta as checked in and issue Divine Gifts at the desk.

The frontend never stores registrations permanently. MongoDB is the source of
truth. The frontend only displays, submits, and briefly caches QR results in
the browser.

2. WHO USES IT AND HOW?
================================================================================

  --- BHAKTAS (General Public) ---
  - Visit the website on phone or computer
  - Register themselves and family members
  - Get a QR / downloadable pass for each person
  - Optionally join volunteer / abhishek / fancy dress / Laddu Gopal
  - Optionally join the referral competition and share their Krishna code
  - Check the public leaderboard (names + counts)
  - Recover a lost pass via Find My Registration (phone + primary DOB)
  - On event day: show QR at the desk to check in and collect Divine Gifts

  --- ORGANISERS ---
  - Watch the home-page live registrant counter
  - Use admin lists/exports for volunteers, abhishek, fancy dress, Laddu Gopal
  - Use the admin leaderboard (includes referral codes, unlike the public page)

  --- SUPER ADMIN ---
  - First account is created once via `npm run seed:super-admin` (not from .env)
  - Full access to every admin page
  - Creates desk / admin users and assigns page permissions at /admin/admins

  --- ADMIN (custom pages) ---
  - Can only open the admin pages granted by super admin
  - Examples: registrations list/export, volunteers, fancy dress, leaderboard

  --- DESK STAFF ---
  - Fixed access: Scanner + Desk Register only
  - Log in at /scanner or /admin
  - Scan Entry QR codes and register walk-ins at the desk

================================================================================

  TanStack Start      — SSR / server wrapper around the router

  Tailwind CSS 4      — Styling
  Framer Motion       — Ambient motion, reveals, confetti
  Radix UI + shadcn   — Button, carousel, and other primitives
  QRCode (npm)        — SVG / PNG QR generation in the browser
  html5-qrcode        — Camera scanner on the desk page
  Lucide React        — Icons
  Embla Carousel      — Gallery, competitions, family QR carousel

  BACKEND
  -------
  Node.js (ESM)       — Runtime
  Express             — HTTP API
  MongoDB + Mongoose  — Registrations, admins, counters, referral logs
  Zod                 — Request validation
  jsonwebtoken        — Staff JWT (role, pages, tokenVersion)
  bcrypt              — Admin password hashes
  Helmet + CORS       — Security headers and origin allow-list
  express-rate-limit  — Register / find / login / referral-validate limits
  Pino                — Logging

  DEPLOYMENT
  ----------
  Frontend: Vercel (TanStack Start / Nitro). vercel.json proxies /api to Railway.
  Backend:  Railway (or any Node host) + MongoDB Atlas.

  Note: Vite/Nitro still lists Cloudflare as a default build target in the
  Lovable config, but this project is deployed on Vercel, not Cloudflare Pages.

5. LOCAL SETUP
================================================================================

  Prerequisites: Node.js 20+, npm, MongoDB URI.

  Backend:
    cd backend
    cp .env.example .env          # set secrets; do not commit .env
    npm install
    npm run seed:super-admin -- <username> <password>
    npm run dev                   # http://localhost:5000

  If login fails for an existing super admin:
    npm run seed:super-admin -- <username> <password> --reset-password

  Frontend:
    cd frontend
    cp .env.example .env
    # VITE_API_URL=http://localhost:5000
    # VITE_PUBLIC_URL=http://localhost:5173
    npm install
    npm run dev

  Then open /admin, sign in, and create desk / admin users under Team access.

7. COMPLETE USER FLOWS
================================================================================

--- FLOW A: NEW REGISTRATION ---

  Step 1: User visits the site or /register (optionally ?ref=KrishnaCode)

  Step 2: Primary fields (all required):
          Full Name, Phone (10-digit Indian mobile), Date of Birth, City
          DOB is a year/month/day picker (not a free-text date).

  Step 3: Referral (optional):
          - "Were you referred?" — Yes/No
          - If Yes: Krishna code field, live-validated (400ms debounce)
          - Green tick / red X from GET /api/validate-referral/:code

  Step 4: Own referral code (optional):
          - "Do you want your own referral code?" — Yes/No
          - If Yes: a unique Krishna name+digits code is issued after submit

  Step 5: Family members (optional):
          - Name + DOB required; phone optional
          - Each member gets their own Entry QR

  Step 6: Seva & celebrations (optional, all default No):
          See §8. Fancy-dress children also receive a general entry pass;
          they do not need to be added again as family members.

  Step 7: Submit → POST /api/register
          Success: result saved to sessionStorage, redirect /success
          Duplicate: message + link to /find
          Other errors: stay on the form

  Drafts: the form writes localStorage every 500ms (key
  janmashtami_register_draft). Draft is cleared after a successful submit.

--- FLOW B: SUCCESS / QR PAGE ---

  Step 1: /success reads sessionStorage. Empty → redirect /register.

  Step 2: Single person → one QR card + Download Pass (PNG).
          Family → carousel, Download Pass / Download All.

  Step 3: Divine Gift reminder under each QR.

  Step 4: If they opted in for a referral code: Krishna code, referral QR,
          WhatsApp / SMS / Copy Link.

  Step 5: Add to Google Calendar (pre-filled with venue, timing, entry codes).

--- FLOW C: FIND MY REGISTRATION ---

  Phone + primary DOB → POST /api/find-registration.
  Found: sessionStorage + /success.
  Not found: friendly empty state.

--- FLOW D: LEADERBOARD ---

  GET /api/leaderboard (max 50 rows, name + count).
  Search by name. Refresh every 60 seconds.

8. SEVA & CELEBRATION OPT-INS
================================================================================

Collected on the public form and desk register. Stored on the primary
registrant document. Admin pages list/export each kind.

  VOLUNTEER  (wantsVolunteer)
  Youth seva. Copy asks volunteers to reach the venue 2 days prior.

  PANCHAMRIT ABHISHEK  (wantsPanchamritAbhishek)
  Divya Panchamrit Abhishek of Nitai–Nimai. Free opt-in.

  FANCY DRESS  (wantsFancyDress + fancyDressEntries[])
  Children under 12. Each entry: childName, childDob, optional getupDetail.
  Categories in site-config: below 6 (parent can accompany), 6–12 (1 min on
  stage). Costume should relate to Sanatan Dharma.
  Public API responses return child first names only — no child DOB or getup.

  LADDU GOPAL  (wantsLadduGopal + ladduGopalSize)
  Free-text size. Bring murti to Utsav Mandapam before 6:00 PM; competition
  entry closes after that.

9. THE REFERRAL / COMPETITION SYSTEM
================================================================================

  1. Bhakta opts in for their own code at registration.

  2. Backend issues a unique code: a Krishna name + 3 digits (e.g. Murari219).
     If collisions persist, it retries with 4 digits.

  3. Share the code, QR, or link:
     https://yourdomain.com/register?ref=Murari219
     Opening that link sets “Were you referred?” to Yes and pre-fills the code.

  4. When a new registration uses a valid code:
     · Self-referral (same phone as the referrer) is ignored
     · Abuse window (10 minutes): ≥5 uses of the same code, or ≥3 from the
       same IP, is logged and does NOT increment the count
     · Otherwise referralCount on the referrer goes up by 1
     · Source is stored as referral-link vs web

  5. Public leaderboard: people with wantsReferral, sorted by count, top 50,
     name + count only.

  6. Competition end datetime is siteConfig.event.competitionEnds
     (currently 5 September 2026). Home page countdown uses this.

  Referral usage is also written to ReferralUsageLog (code, IP, memberCount,
  flaggedForAbuse) for later review.

10. THE QR CODE SYSTEM
================================================================================

ENTRY QR:

  Payload format:  ENTRYCODE.HMAC_SHA256_HEX
  Example:         JN2026-00452.<64-char hex>

  HMAC is computed over the entry code with HMAC_SECRET (backend).
  The browser only renders the payload; it cannot mint a valid signature.

  Entry codes come from a Mongo Counter: JN{EVENT_YEAR}-{5-digit seq}
  e.g. JN2026-00001.

  Download Pass PNG includes: event name, QR, full name, entry code,
  Divine Gift note, date and venue.

REFERRAL QR:

  Encodes the referral URL (VITE_PUBLIC_URL/register?ref=Code).
  Scanning it opens the form with the code pre-filled.

Generation is entirely client-side via the qrcode package.

11. THE SCANNER / CHECK-IN SYSTEM
================================================================================

Used on /scanner and /admin/scanner. Not in public nav.

--- LOGIN ---

  POST /api/admin/login  (rate limited: 5 / minute)
  Accounts are in MongoDB Admin (roles: super_admin, admin, desk).
  JWT includes role, pages, tokenVersion. Default expiry JWT_EXPIRY=2h.
  Token + profile stored in sessionStorage (cleared when the tab closes).
  Changing password or disabling a user bumps tokenVersion and invalidates
  old tokens. The scanner page requires the "scanner" page permission.

--- SCANNING ---

  Camera via html5-qrcode at 10 fps (see scanner-config.js).
  Detected payload → POST /api/scan/checkin with Bearer JWT.

  SUCCESS:            green card — name, checked in, gift issued, time
  ALREADY CHECKED IN: red card — name + original check-in time
  NOT FOUND:          red card
  SIGNATURE MISMATCH: red card — entry code filled into manual box

  Check-in also sets freebieClaimed / freebieClaimTime and verifiedBySignature.

--- MANUAL OVERRIDE ---

  Type JN2026-xxxxx → POST /api/scan/checkin/override with a reason.
  Same JWT + scanner permission.

--- LOGOUT ---

  Exit / Log out clears sessionStorage.

  401 → session cleared. Nav hides pages the user cannot open; visiting a

13. BACKEND (API, MODELS, SERVICES)
================================================================================

  Envelope:
    Success  { "success": true, "data": ... }
    Error    { "success": false, "error": { "code", "message" }, ... }

  GET /health  — { ok: true }  (not under /api)

  CORS: CORS_ORIGIN is a comma-separated allow-list. In development, any
  http://localhost:<port> origin is also allowed (Vite port may vary).

  Body size: express.json limit 64kb.
  Trust proxy: only when NODE_ENV=production or TRUST_PROXY=true.

  Rate limits (per IP, 1-minute window):
    POST /api/register              10
    GET  /api/validate-referral/*   30
    POST /api/find-registration     20
    POST /api/admin/login            5

  MODELS
  ------
  Registration  — person (primary or family member). Unique entryCode.
                  Unique sparse (phone, dob). Optional referralCode.
                  Opt-in flags, fancyDressEntries, ladduGopalSize,
                  checkedIn, freebieClaimed, registrationSource
                  (web | referral-link | desk-manual).

  Admin         — username (lowercase unique), passwordHash, role, pages,
                  isActive, tokenVersion, createdBy.

  Counter       — _id "entryCode", seq for JN{year}-{nnnnn}.

  ReferralUsageLog — audit of referral attempts (abuse flags).

  KEY SERVICES
  ------------
  registration.service   create family group, codes, credit referral
  duplicateCheck         phone+DOB already registered → use /find
  fraudCheck             self-referral + burst limits
  hmac.service           sign / verify / buildSignedPayload
  entryCode.service      JN{EVENT_YEAR}-{seq}
  referralCode.service   Krishna name + digits
  shapeRegistration      public JSON: signedPayload, redact child DOB/getup

  GET /api/registration/:id was removed (unauthenticated IDOR that returned
  signed QR payloads). Use find-registration or the register response.

16. ENVIRONMENT VARIABLES

  -------------------------------

  Admins live in MongoDB.

  FRONTEND
  --------

                   Production: leave empty so the site uses same-origin /api
                   (vercel.json proxies to Railway). Do not set a
                   *.railway.app URL — some ISPs block it. Localhost values
                   are ignored in production builds.

  VITE_PUBLIC_URL  Public site origin, no trailing slash.
                   Used for referral share links and calendar/meta.
                   Production example: https://aanandotsav.vercel.app

19. KNOWN LIMITATIONS AND NOTES FOR DEVELOPERS
================================================================================

  · HMAC_SECRET must stay stable for the whole event. Changing it invalidates
    every already-downloaded QR.

  · Public leaderboard is not WebSocket-live; it polls every 60 seconds.

  · QR results live in sessionStorage. Closing the tab before download means
    the bhakta must use Find My Registration. That is intentional.

  · Scanner needs camera + HTTPS (required on iOS Safari).

  · Fonts (Marcellus, Mulish) load from Google Fonts. If blocked, the site
    falls back to system serif/sans.

  · nitro in frontend/package.json is a beta pin (3.0.260603-beta).

  · Production errors currently go to console via lovable-error-reporting.js.
    Wire Sentry there if you want event-day alerting.

  · Social links in site-config.js are still empty (Instagram / Facebook /
    YouTube). Phone and email for the seva desk are filled.

  · Gallery files in public/gallery/ are SVG placeholders until real photos
    are added (see MEDIA_GUIDE.md).

  · Prizes array in site-config.js is empty until official prizes are set.

  · Duplicate detection: primary is phone + DOB; family members (including
    fancy-dress children auto-added as members) are name + DOB. Fancy-dress
    children are also stored on the primary document’s fancyDressEntries.

  · Rate limits are per IP. Behind a proxy, TRUST_PROXY / production
    NODE_ENV must be set or every client may share one bucket.
