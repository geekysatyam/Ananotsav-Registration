1. WHAT IS THIS PROJECT?
================================================================================

Anandotsav 2026 is the Sri Krishna Janmashtami celebration held at
Sri Gokul Gaushala, Birbalpura, Amritsar on Sunday, 6 September 2026.

This repository is the FULL registration platform (website + API + database).
It does five things:

  A) REGISTRATION
     People register themselves and family members. Each person gets a unique
     Entry QR code and an entry pass they can download.

  B) SEVA & CELEBRATIONS
     During registration, bhaktas can optionally opt in for:
     · Youth volunteer seva
     · Divya Panchamrit Abhishek
     · Fancy dress for kids (age 12 or under)
     · Laddu Gopal shringar (bring murti to Utsav Mandapam before 6:00 PM)
     Staff can list and CSV-export each of these from the admin panel.

  C) REFERRAL COMPETITION — CURRENTLY PAUSED
     Code and models remain in the repo but the public UI / credit path is
     disabled. See §9. Fancy dress and Laddu Gopal competitions still run.

  D) EVENT CHECK-IN (SCANNER)
     On event day, staff scan each Entry QR (or type the entry code) to mark
     the bhakta as checked in and issue Divine Gifts at the desk.

  E) WHATSAPP ENTRY PASS (optional)
     After a successful PUBLIC registration, the backend queues a non-blocking
     WhatsApp message with the same signed Entry QR as the website.
     Desk / admin register does NOT send WhatsApp. See §13 and backend/WHATSAPP.md.
     Railway setup notes: whatsappguide.txt.

The frontend never stores registrations permanently. MongoDB is the source of
truth. The frontend only displays, submits, and briefly caches QR results in
the browser.

2. WHO USES IT AND HOW?
================================================================================

  --- BHAKTAS (General Public) ---
  - Visit the website on phone or computer
  - Register themselves and family members
  - Get a QR / downloadable pass for each person
  - Optionally receive the Entry Pass on WhatsApp (when enabled + paired)
  - Optionally join volunteer / abhishek / fancy dress / Laddu Gopal
  - Recover a lost pass via Find My Registration (phone + primary DOB)
  - On event day: show QR at the desk to check in and collect Divine Gifts

  --- ORGANISERS ---
  - Watch the home-page live registrant counter
  - Use admin lists/exports for volunteers, abhishek, fancy dress, Laddu Gopal

  --- SUPER ADMIN ---
  - First account is created once via `npm run seed:super-admin` (not from .env)
  - Full access to every admin page
  - Creates desk / admin users and assigns page permissions at /admin/admins
  - Manages WhatsApp pairing, queue, and retries at /admin/whatsapp

  --- ADMIN (custom pages) ---
  - Can only open the admin pages granted by super admin
  - Examples: registrations list/export, volunteers, fancy dress
  - Cannot open /admin/whatsapp (super_admin only)

  --- DESK STAFF ---
  - Fixed access: Scanner + Desk Register only
  - Log in at /scanner or /admin
  - Scan Entry QR codes and register walk-ins at the desk
  - Walk-ins do not receive WhatsApp QR (QR is shown on site)

5. LOCAL SETUP
================================================================================

  Prerequisites: Node.js 20+, npm, MongoDB URI.

  Backend:
    cd backend
    copy .env.example .env        # Windows CMD; set secrets; do not commit .env
    npm install
    npm run seed:super-admin -- <username> <password>
    npm run dev                   # http://localhost:5000

  WhatsApp (optional):
    Set WHATSAPP_ENABLED=true and PUBLIC_APP_URL in backend/.env
    npm run whatsapp:login        # or pair from Admin → WhatsApp
    npm run whatsapp:status

  Frontend:
    cd frontend
    copy .env.example .env
    REM VITE_API_URL=http://localhost:5000
    REM VITE_PUBLIC_URL=http://localhost:5173
    REM VITE_WHATSAPP_CONFIRMATION_HINT=true   (optional success-page hint)
    npm install
    npm run dev

  Then open /admin, sign in, and create desk / admin users under Team access.

7. COMPLETE USER FLOWS
================================================================================

--- FLOW A: NEW REGISTRATION (PUBLIC) ---

  Step 1: Visit /register

  Step 2: Primary fields (required):
          Full Name, Phone (10-digit Indian mobile), Date of Birth, City
          DOB picker: max = yesterday (not today or future).
          If fancy dress: DOB must imply calendar age ≤ 12.

  Step 3: Family members (optional) — skipped when fancy dress is Yes
          (child is the primary registrant for that path).

  Step 4: Seva & celebrations (optional). Fancy dress may include optional
          parent name + getup detail.

  Step 5: Submit → POST /api/register
          · MongoDB write + entry codes + signed payloads
          · HTTP 201 immediately (never waits on WhatsApp)
          · Queue WhatsAppMessage for primary (if WA enabled) — fire-and-forget
          · Redirect /success with sessionStorage result

  Desk path: POST /api/admin/register with registrationSource=desk-manual.
  Auto check-in + freebie; NO WhatsApp queue.

--- FLOW B: SUCCESS / QR PAGE ---

  sessionStorage → QR cards, Download Pass, calendar.
  Optional WA hint. Referral share UI is paused with the competition.

--- FLOW C: FIND MY REGISTRATION ---

  POST /api/find-registration → /success.

10. THE QR CODE SYSTEM
================================================================================

ENTRY QR:

  Payload:  ENTRYCODE.HMAC_SHA256_HEX
  HMAC over entry code with HMAC_SECRET (backend only).
  Entry codes: JN{EVENT_YEAR}-{5-digit} from Mongo Counter.

  Website Download Pass and WhatsApp image both use the SAME signed payload
  via buildSignedPayload(entryCode) — never a different QR for WhatsApp.

REFERRAL QR: paused with the competition.

13. WHATSAPP ENTRY PASS (BAILEYS)
================================================================================

  PURPOSE
  -------
  Transactional confirmation only after PUBLIC POST /api/register.
  Image = Entry QR PNG (same HMAC payload). Caption = name, entry code,
  date/venue, optional family /find link.

  NON-BLOCKING
  ------------
  Registration always returns 201 on DB success. WhatsApp failures never
  fail the HTTP response.

  PERSISTENT QUEUE (MongoDB WhatsAppMessage)
  ------------------------------------------
  Statuses: pending → processing → sent | failed | cancelled
  uniqueKey = registrationId:registration-qr (unique index — no duplicates)
  Survives Railway / Node restart. Stuck “processing” jobs reset to pending
  on worker start. Offline: jobs stay pending; auto-resume when connected.
  Change number: cancels pending/processing (not auto-sent on new number).

  WORKER
  ------
  · One message at a time (WHATSAPP_MAX_CONCURRENT_SENDS=1)
  · FIFO by queuedAt
  · Random delay between sends (MIN/MAX_DELAY_MS) — controlled delivery,
    not a claimed WhatsApp-safe rate
  · Exponential backoff retries up to WHATSAPP_MAX_ATTEMPTS
  · Circuit breaker after consecutive failures (cooldown then resume when healthy)
  · No bulk / broadcast / marketing endpoints

  DESK REGISTER
  -------------
  registrationSource desk-manual → never auto-queued; retry APIs reject desk.

  ADMIN UI  /admin/whatsapp
  ------------------------
  Connection status, queue counts, worker state, offline “safely queued”
  banner, pair (QR or phone code), reconnect / disconnect / change number,
  message history + per-message retry.

  Ops detail: backend/WHATSAPP.md
  Railway volume / env: whatsappguide.txt

18. DEPLOYMENT
================================================================================

  Frontend — Vercel. Production: VITE_PUBLIC_URL only (no VITE_API_URL).
  vercel.json rewrites /api and /health → Railway.

  Backend — Railway + MongoDB Atlas.

  · Persistent volume mounted at WHATSAPP_SESSION_DIR
  · WHATSAPP_ENABLED=true, PUBLIC_APP_URL=Vercel origin
  · Queue in MongoDB survives restarts; session restores from volume
  · See whatsappguide.txt and backend/WHATSAPP.md

20. KNOWN LIMITATIONS AND NOTES FOR DEVELOPERS
================================================================================

  · HMAC_SECRET must stay stable for the whole event.

  · QR results live in sessionStorage; use Find My Registration if the tab
    was closed before download.

  · Scanner needs camera + HTTPS (iOS Safari).

  · Referral competition is paused — do not promise it on marketing copy.

  · WhatsApp is optional and transactional only. No bulk send.
    Desk register never auto-sends. Public register never blocks on WA.

  · Pairing codes / session keys must never be logged or committed.

  · TanStack routeTree.gen.js must include new admin routes (e.g. whatsapp)
    or the nav link shows “Not Found”.

  · Rate limits are per IP; set TRUST_PROXY behind a reverse proxy.
